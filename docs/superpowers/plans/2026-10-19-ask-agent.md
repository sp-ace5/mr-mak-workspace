# Ask Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a failing asset in the Studio, **Ask agent** puts that asset's gate failures and source paths into the active chat's composer as a draft, never sent, and brings the Chats window forward.

**Architecture:** One new authorized route `POST /api/chats/draft {text, sessionId?}` in `server.mjs` broadcasts a `chat-draft` event and reuses the existing `show('chats', {sessionId})` (native window show + `navigate`). The Chats window appends the text to that chat's draft, stored in `localStorage` (`mrmak.chatDraft.<id>`, the key `Conversation.tsx` already uses), and an open `Conversation` reloads it. Nothing is ever sent to the agent by this path.

**Tech Stack:** Node service, React (`src/desktop`, `src/studio`), `node:test`, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-18-asset-studio-design.md` §4: "Ask agent: sends a failing asset's gate results plus source path to the active chat as a draft message (not auto-sent)." §5: agents fix the source, never `build/` outputs, and never run `approve`/`publish`.

## Global Constraints

- Draft only: the route must not call `sessions.send` or write to a PTY. The user presses Send.
- "Active chat" = `sessionId` if given, else the service's selected chat. No chat → 409 "Open a chat first".
- Text limit 8 KB (400 otherwise), string only.
- Appending, not replacing: an existing draft is kept, with a blank line before the new text.

## Decisions

- Message text (built in the Studio):
  ```
  Asset factory: <pack>/<name> (<kind>) failed its gates on attempt <n>:
  - <gate>: measured <measured>, expected <expected>
  Sources: factory/spec/packs/<pack>.yaml[, factory/shaders/<pack>/<name>.gdshader for shaders]
  Fix the source (generator, shader or spec), never files under factory/build/. Then rebuild with
  `node scripts/run-python.mjs factory/pipeline/run.py build --pack spec/packs/<pack>.yaml --json`.
  Do not run approve or publish. See the asset-factory skill.
  ```
- Button shown only for `failed` assets that have at least one failed gate.
- Studio feedback: "Draft added to <chat name>" (`role="status"`), or the 409/400 message.

## Review Focus

1. Chats window closed or hidden → the native `show` opens it; the draft is in storage, so the chat shows it when it mounts.
2. The target chat is not the selected one in the Chats window → `navigate` selects it, and the draft appears there, not in the previously open chat.
3. A draft with images/paths attached → `paths` survive; only `text` is appended.
4. Two quick clicks → both blocks appear once each, in order (no lost update between storage and React state).
5. Mobile clients receive the event and ignore it (no crash).

- `client.ts`: `appendChatDraft(sessionId, text)` (exported for tests is not needed): read `mrmak.chatDraft.<id>`, set `text = old ? old.trimEnd() + '\n\n' + text : text`, keep `paths`, write back, then `window.dispatchEvent(new CustomEvent('mrmak-chat-draft', { detail: sessionId }))`. Only on `surface === 'chats'`.
- `Conversation.tsx`: on `mrmak-chat-draft` with `detail === session.id`, `setDraft(savedDraft(session.id))` and focus the textarea.
